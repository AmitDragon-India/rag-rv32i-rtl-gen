### Branch and Jump Resolution

Branch comparison and target address generation are separate operations.

#### Branch comparison
- Uses `rs1_data` and `rs2_data`
- Comparison result (`branch_taken`) determines whether branch redirects PC

#### Branch target
```
branch_target = pc_in + imm_b
```

#### Jump targets
```
JAL  target = pc_in + imm_j
JALR target = (rs1_data + imm_i) & ~32'h1   // clear LSB
```

#### Redirect logic
- Jumps always redirect the PC
- Branches redirect only when `branch_taken = 1`
- On redirect: flush IF and ID pipeline registers (insert NOP = `32'h00000013`)

## Wiring Rules

1. IF stage has internal imem — no external imem ports on rv32i_top
2. Data memory is a logic array inside rv32i_top — dmem_* wires connect to mem_stage ports
3. alu_control takes opcode/funct3/funct7 from IF/ID register bits directly
4. regfile rs1_addr = if_id_instr[19:15], rs2_addr = if_id_instr[24:20]
5. wb_data feeds back to ex_stage.wb_data for MEM/WB forwarding
6. ex_mem_alu_result feeds back to ex_stage.ex_mem_alu_result for EX/MEM forwarding
7. pc_next = ex_redirect_en ? ex_redirect_pc : if_pc_plus4
8. stall_pc connects to if_stage.stall
9. flush_if_id connects to if_stage.flush AND IF/ID register flush
10. flush_id_ex flushes both ID/EX and EX/MEM registers
11. EX/MEM register takes reg_write/mem_read/mem_write/wb_sel from EX stage outputs
    NOT directly from ID/EX register — EX stage passes them through

## Common Bugs to Avoid

- Making reads synchronous (registered) — causes one-cycle read delay breaking pipeline timing
- Missing write-before-read bypass — causes stale register reads when WB and ID access the same register simultaneously
- Forgetting `rd_addr != 5'b0` guard on write — allows corrupting the hardwired-zero register
- Using `assign` for reads when bypass logic is needed — use `always_comb` instead
